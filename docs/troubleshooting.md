# Ошибки и диагностика Q6A

## UART

Для уже проверенного подключения используйте 115200, 8N1, без flow control,
и включите PuTTY Session → Logging до подачи питания.
По [документации Radxa](https://docs.radxa.com/en/dragon/q6a/system-config/uart-debug):

| Q6A, физический пин 40-pin разъёма | USB UART адаптер |
| --- | --- |
| 6, GND | GND |
| 8, TX | RX |
| 10, RX | TX |

VCC адаптера не подключается. Плата питается от своего источника.
Используйте проверенный адаптер и подключение; не меняйте провода при поданном питании.

## Ошибки EDL

| Сообщение | Что проверить |
| --- | --- |
| `No Qualcomm EDL devices found` | Нижний USB A OTG порт, кабель, питание, драйвер и вход в EDL |
| `Unknown`, QUD read/write timeout | Свежий вход в EDL; повторить остановившуюся стадию |
| Host payload 1048576, Lite supports 16384 | Замороженный edl-ng v2 и `--maxpayload 16384`; исходная утилита игнорировала это в provisioning |
| Configure NAK после смены SPI/UFS | Сначала новый Sahara, затем нужный программатор; один `--loader` текущий Firehose не заменяет |
| `9/10 commands succeeded`, commit NAK | Provision не завершён; запись системы не начинать |
| Partition not found после серии тайм-аутов | Сначала восстановить транспорт; тайм-аут не доказывает отсутствие раздела |
| SHA256 mismatch / неполное чтение | Остановиться, сохранить лог и readback; Boot не выполнять |
| Отсутствует файл из rawprogram XML | Восстановить точный пакет; не игнорировать ошибку |
| QFIL `invalid EDL state` | Эта попытка не дала успеха; в воспроизводимый маршрут включён исправленный edl-ng |

Даже при нулевом коде выхода `[ERROR]` означает остановку. Сценарий не принимает
строку `command finished successfully`, если в той же операции был ERROR.
Для SPI сектор имеет размер 4096 байт; полный образ — 8192 сектора, 32 МиБ.

## Зелёный светодиод и пустой экран

Светодиод сам по себе не определяет стадию загрузки. Сохраните весь UART с подачи питания.

| Последняя стадия | Значение и следующий шаг |
| --- | --- |
| `UFS INQUIRY ID` и `UFS Boot LUN: 1` | XBL увидел устройство; это ещё не запуск Android |
| DDR обнаружена, затем `UFS 3.x Device Volt set to 2.5 volt` | Прежняя точка зависания stock XBL; сверить исправленные UFS и SPI |
| APDP/AOP/QSEE/APPSBL | XBL прошёл дальше; дождаться UEFI и ядра |
| `Booting Linux`, но нет интерфейса | Сохранить kernel UART, проверить ADB `sys.boot_completed` и вывод HDMI |
| ADB `sys.boot_completed=1`, интерфейс есть | Запуск Android подтверждён; отдельно нужен холодный старт |

Полное обратное чтение XBL и SPI отделяет неправильную запись от поведения
правильно записанного образа. Если оно не совпадает, повторная загрузка ничего
не доказывает. В таком случае сначала разберите лог или верните бэкап.

## Что не вошло в рабочий путь

- Стирание DDR раздела без установленной причины.
- Обход EDL записью Android из Linux через произвольный `dd`.
- Предположение, что любой UFS 3.0 требует одного конкретного напряжения.
- Игнорирование configure NAK или отсутствующих образов.
- Повторный provisioning уже настроенного модуля.

Для Linux используйте [прямую прошивку BIOS](linux-bios.md).
