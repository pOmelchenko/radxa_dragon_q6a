# Конфигурация и проверка решений

## Linux BIOS

Версия файлов — официальный Linux BIOS `260120`. Повторная запись при переходе
с рабочего Android BIOS проверена обратным чтением полного SPI и сравнением
18 payload: [linux-spi-260120.json](linux-spi-260120.json).
После записи проверены самостоятельные загрузки Radxa OS R2 с SD и NVMe,
описанные ниже.

Для официального набора `260916`, закреплённого на коммите
`48835fa3de36ea80597cf39e7a41a9ddf9648f52`, также проверены запись SPI,
совпадение 18 payload и CRC обеих GPT:
[linux-spi-260916.json](linux-spi-260916.json).
Эта запись фиксирует результат прошивки BIOS; версии для установки ОС
указаны в руководствах по соответствующему носителю.

## Android на Toshiba UFS

На Q6A 12 ГБ с `THGJFCT2T84BAKCB rev 0100`, UFS 3.0, 512 ГБ проверен переход
с Linux на Android 15 `20260630-b1`. После записи через Lite прочитаны и
сверены все 48 записанных payload, 3861059241 байт; обе GPT всех шести LUN
прошли проверку CRC. Исправленный `xbl_a`, полный SPI из официальных файлов
и новая пустая ext4 metadata совпали с кандидатами при обратном чтении.
Конфигурация UFS сохранена, provisioning повторно не выполнялся:
[android-image-write-2026-10-11.json](android-image-write-2026-10-11.json).

После первого успешного запуска, обычной перезагрузки и двух холодных включений получены
`sys.boot_completed=1`, остановленная boot animation, успешная отметка
слота A, writable ext4 `/metadata` и зашифрованная F2FS `/data`.
Интерфейс HDMI подтверждён пользователем, активен режим 3840×2160 @ 30 Hz.
После сброса буферов и 45 секунд простоя на каждом из четырёх запусков прочитан 1 ГиБ
без ошибок UFS; ID загрузки за время чтения не изменился.
Чтение заняло 1,059 / 0,873 / 0,812 / 0,810 секунды соответственно.
Штатный Toybox не поддерживает O_DIRECT, поэтому проверялось буферизированное
чтение блочного устройства. В этих проверках, до штатного сброса,
размер `/data` составлял 45 ГиБ:
[android-boot-2026-10-11.json](android-boot-2026-10-11.json).

Первоначальное решение с provisioning и сохранённым снимком SPI зафиксировано
отдельно: [hardware-results.json](hardware-results.json),
[direct-route-evidence.json](direct-route-evidence.json).
Текущая [инструкция Android](../../guides/android-ufs.md) использует воспроизводимую
сборку из официальных файлов; личный снимок SPI для неё не требуется.

## Полный объём Android /data

Штатный recovery выполнил `--wipe_data` на том же Toshiba UFS.
Новая F2FS занимает 465940300 КиБ (444,36 ГиБ) при разделе userdata
477124964352 байта. Запрос recovery записан в первые 2048 байт `misc`,
прочитан обратно и проверен; следующие 2048 байт со сведениями о слотах
сохранились. Процедура удаляет данные и создаёт новую конфигурацию шифрования.

После сброса проверены Android 15, `sys.boot_completed=1`, успешный слот A,
FBE, metadata encryption и SELinux Enforcing. Файл 64 ГиБ получил реальное
выделение блоков, а записанные в его конец 8 МиБ прочитаны с совпадающим
SHA-256. После обычной перезагрузки сохранились размер `/data` и хеш
отдельного файла 8 МиБ. Затем выполнено чтение 1 ГиБ UFS после 45 секунд
простоя; ошибок UFS в этих запусках нет. Тестовые файлы удалены.

Команды: [полный объём /data](../../guides/android-data-capacity.md).
Отдельная запись результата сохраняет исторические проверки исходной
файловой системы: [android-data-capacity-2026-10-11.json](android-data-capacity-2026-10-11.json).

## Запись Radxa OS R2 на SD

На Windows образ `radxa-dragon-q6a_noble_gnome_r2.output_512.img` записан через
EDL в SD 32 ГБ (`Sdcc`, слот 1). Обратное чтение всех 6003352576 записанных
байт совпало с SHA-256 исходного образа:
[sd-image-write-2026-10-10.json](sd-image-write-2026-10-10.json).
Эта запись фиксирует проверку содержимого карты до первого запуска ОС.

После холодного включения открыт рабочий стол и проверен доступ по SSH.
Корень находится на `/dev/mmcblk1p3`, EFI — на `/dev/mmcblk1p2`; других физических
накопителей в системе нет. Раздел корня автоматически расширился до 30161223168
байт, GPT прошла проверку `sfdisk`. Ядро `6.18.2-3-qcom`, параметры штатной записи
загрузчика, активных дополнительных оверлеев нет. Сервер OpenSSH установлен
при первом входе и включён при загрузке:
[sd-boot-2026-10-10.json](sd-boot-2026-10-10.json).

## Запись Radxa OS R2 на NVMe

Образ с секторами 512 байт записан через EDL на KIOXIA `KBG40ZNS256G`,
256060514304 байта. Использованы Linux DDR программатор `260120`,
`--memory Nvme`, LUN 0. Запись всех 6003352576 байт заняла 25,73 секунды;
полное обратное чтение записанной области — 137,51 секунды.
SHA-256 обратного чтения совпал с исходным образом:
[nvme-image-write-2026-10-10.json](nvme-image-write-2026-10-10.json).
Сравнение выполнено до первого запуска ОС.

Корень и EFI проверены на `/dev/nvme0n1p3` и `/dev/nvme0n1p2`;
остальные физические носители отключены. Корневой раздел автоматически
расширился до 254953201152 байт, файловая система — до 250830680064 байт,
GPT прошла проверку. После обновления `apt upgrade -y` проверены программная
перезагрузка и холодное включение с ядром `7.0.11-7-qcom`, доступ по SSH
и прямое чтение 1 ГиБ. Дополнительных активных оверлеев нет, параметры
совпадают со штатной записью загрузчика, созданной обновлёнными пакетами.
Экран входа после холодного включения подтверждён пользователем:
[nvme-boot-2026-10-10.json](nvme-boot-2026-10-10.json).

Обновление пакетов и ядра для SD, NVMe и UFS описано в
[общей инструкции Radxa OS](../../guides/linux-update.md). Она использует
рекомендованный Radxa маршрут через `rsetup`. Результат выше сохраняет
фактический APT-прогон; аппаратная проверка через `rsetup` отдельно
не зафиксирована.

## Запись Radxa OS R2 на UFS

Образ с секторами 4096 байт записан через EDL в LUN 0 Toshiba
`THGJFCT2T84BAKCB0100`, 496714645504 байта. Использованы Lite программатор
из официального Linux BIOS `260120` и `--maxpayload 16384`.
Конфигурация UFS сохранена; provisioning и запись остальных LUN не выполнялись.
Запись всех 10737418240 байт заняла 349,22 секунды, полное обратное чтение —
269,55 секунды. SHA-256 совпал с исходным образом:
[ufs-image-write-2026-10-10.json](ufs-image-write-2026-10-10.json).
Эта запись подтверждает содержимое LUN 0 до первого запуска Linux.

Для маршрута с BIOS `260916` выполнена повторная запись того же образа
через Lite программатор из закреплённого набора BIOS. Запись 10737418240 байт
заняла 320,67 секунды, полное чтение — 276,39 секунды; SHA-256 совпал:
[ufs-image-write-260916-2026-10-10.json](ufs-image-write-260916-2026-10-10.json).

## Загрузка Radxa OS R2 с Toshiba UFS

На BIOS `260916` и исходном ядре R2 `6.18.2-3-qcom` установлена постоянная
настройка питания Toshiba через udev/initramfs. Правило сопоставляет
сохранённые SCSI vendor/model после обнаружения LUN, оставляет контроллер
и логические устройства активными. Правило и помощник включены в initramfs;
копия на EFI совпала с `/boot`.

Проверены обычная программная перезагрузка и два холодных включения,
экран входа Ubuntu, SSH и автоматическое применение настройки на каждом
запуске. После 45 секунд простоя прочитаны 4 ГиБ: 956, 891 и 882 МБ/с.
Ошибок UFS, сбросов, I/O error и kernel panic в этих проверках не обнаружено.
Дополнительных активных оверлеев нет. BIOS сам добавляет `clk_ignore_unused`;
временные `init=/bin/bash` и параметры восстановления не сохраняются.

Корень и EFI находятся на третьем и втором разделах UFS LUN 0.
GPT проверена, корневая файловая система автоматически расширилась
до 487458680832 байт, примерно 454 ГиБ. Другие физические носители сняты.
Команды: [Linux на UFS](../../guides/linux-ufs.md).
Машиночитаемые результаты:
[ufs-boot-2026-10-10.json](ufs-boot-2026-10-10.json).

## Проверка инфраструктуры

CI выполняет проверку документации и общих инструментов на Windows, macOS
и Linux. Отдельно выполняются проверки Windows-автоматизации без USB.
Актуальный результат:
[GitHub Actions](https://github.com/pOmelchenko/radxa_dragon_q6a/actions).

[offline-2026-10-10.json](offline-2026-10-10.json) фиксирует исходную проверку
патча edl-ng, сборки XBL, пакетов и Windows-обёрток. Это техническая запись
для разработки; руководство по прошивке использует прямые команды.
