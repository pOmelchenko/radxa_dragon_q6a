# BIOS для Linux и Android

В SPI платы хранится одна загрузочная прошивка. Для Linux она общая для
SD, NVMe и UFS; при переходе между Linux и Android меняется комплект SPI:

| Система | Состав SPI | Рабочая команда и результат |
| --- | --- | --- |
| Linux на SD/NVMe/UFS | Один выбранный Linux BIOS: XBL с LBA 925, XBL_CONFIG, AOP, TZ, UEFI и другие компоненты | [Выбор версии и получение файлов](../guides/prepare-edl.md#linux), затем [единая запись SPI](../guides/linux-bios.md); результаты испытаний — в [разделе проверки](validation/README.md) |
| Android на Toshiba UFS | Android SPI: GPT и исправленный XBL с LBA 6; следующие компоненты — на UFS | [Запись Android SPI](../guides/android-ufs.md#записать-исправленный-android-spi); полный SPI совпал с readback, Android завершил загрузку |

## История версий Linux BIOS

`260120` и `260916` — версии общего Linux BIOS для платформы QCS6490.
Единственный выбор для установки находится в
[общей подготовке](../guides/prepare-edl.md#linux). Здесь приведены происхождение
версий и сведения производителя.

Официальная история версий есть в
[changelog пакета edk2-qualcomm](https://github.com/radxa-pkg/edk2-qualcomm/blob/48835fa3de36ea80597cf39e7a41a9ddf9648f52/debian/changelog).
Номер пакета и дата сборки BIOS различаются:

| BIOS QCS6490 | Выпуск пакета | Опубликованные сведения |
| --- | --- | --- |
| `260120` | `0.1.0-5`, 14 февраля 2026 | Прошивка от 20 января 2026; [подробное описание Radxa](https://forum.radxa.com/t/radxa-dragon-q6a-firmware-snapshot/28886/20): новая база Qualcomm для Windows/Linux, HDMI в UEFI, сетевая загрузка, выбор DTB по ядру и другие изменения |
| `260916` | `0.1.0-8`, 17 сентября 2026 | Обновление QCS6490 до `6.0.260916.BOOT.MXF.1.0.1-00549-KODIAKWP-1`; [коммит обновления](https://github.com/radxa-pkg/edk2-qualcomm/commit/5dd3e003376828ebbfd8540689a176c5013e9d1f) |

Changelog `260916` сообщает номер прошивки, без перечня исправлений UFS.
Он подтверждает происхождение версии, но не доказывает, что Toshiba требует
именно её или что новая прошивка сама устраняет проблему энергосбережения.
Основание выбора в руководстве — [проверенная конфигурация Toshiba](validation/ufs-boot-2026-10-10.json):
BIOS `260916`, ядро `6.18.2-3-qcom` и постоянная настройка питания UFS,
с перезагрузкой, двумя холодными включениями и чтением после простоя.

## Подготовка и смена ОС

Сначала выберите ОС и подготовьте соответствующие файлы из
[справочника прошивок](firmware-files.md). Команда Linux записывает BIOS в SPI;
система устанавливается отдельно, например по [проверенному маршруту SD](../guides/linux-sd.md).
Android требует установленной системы и исправленного `xbl_a` в UFS.

При переходе к Linux используйте руководство Linux BIOS. Для уже установленного
Android доступна [запись только Android BIOS](../guides/android-ufs.md#вернуть-только-android-bios-при-установленной-системе).
Перед записью сохраняется полный SPI, затем проверяется обратное чтение.

В [bios-profiles.json](../../firmware/bios-profiles.json) перечислены хеши
сохранённых полных SPI-образов первоначального комплекта. Проверка пакета сверяет эти файлы.
Текущий Android SPI собирается из официальных файлов командой `prepare-android`;
его хеш закреплён отдельно в
[Android files.lock.json](../../firmware/android15-ufs-toshiba512/files.lock.json).
Для Linux основная команда использует rawprogram, а полный снимок сохраняется
как артефакт восстановления.
