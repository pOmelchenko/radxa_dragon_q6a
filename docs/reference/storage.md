# Накопители и загрузка

## Расположение системы

| Компонент | Назначение в рабочей конфигурации |
| --- | --- |
| SPI NOR, 32 МиБ | Загрузочная прошивка; вариант зависит от ОС |
| NVMe, 256 ГБ | KIOXIA KBG40ZNS256G; Radxa OS R2 с обновлением до ядра `7.0.11-7-qcom`, SSH и холодная загрузка |
| Toshiba UFS, 512 ГБ | Android 15 или Radxa OS R2 с BIOS 260916 и настройкой питания UFS |
| microSD, 32 ГБ | Штатная Radxa OS R2, ядро `6.18.2-3-qcom`, рабочий стол и SSH |

Запись BIOS меняет SPI, а установка Android по `rawprogram` меняет UFS.
Ubuntu на NVMe сохраняется при отдельной записи SPI.
[Основной Linux BIOS](../guides/prepare-edl.md#linux) общий для SD, NVMe и UFS;
образы ОС перечислены в [справочнике файлов](firmware-files.md).

## Linux

Штатная Radxa OS R2 проверена [установкой на SD через EDL](../guides/linux-sd.md).
Корневой раздел и файловая система расширились на доступный объём карты
при первом запуске. Дополнительные оверлеи выключены, параметры ядра исходные.
Команды записи загрузочной прошивки: [Linux BIOS](../guides/linux-bios.md).

Во всех трёх Linux-маршрутах используется один дистрибутив Radxa OS R2.
Обновление пакетов и ядра выполняется по
[общей инструкции для SD, NVMe и UFS](../guides/linux-update.md);
для Toshiba отдельно проверяются initramfs нового ядра и настройка питания.

Для [NVMe](../guides/linux-nvme.md) дополнительно проверено обновление пакетов
через APT, программная перезагрузка и холодное включение с ядром
`7.0.11-7-qcom`. В обоих маршрутах активных дополнительных оверлеев нет.

В проверенной конфигурации [Toshiba UFS](../guides/linux-ufs.md) использовались
BIOS `260916`, исходное ядро `6.18.2-3-qcom` и настройка питания через udev/initramfs.
Корень располагается в LUN 0 и автоматически расширяется: файловая система
487458680832 байта, примерно 454 ГиБ. Остальные LUN сохраняются.

Для SD/NVMe используется образ R2 с логическими секторами 512 байт,
для UFS — 4096 байт. Точные файлы закреплены в
[описании выпуска](../../firmware/radxa-os-r2/images.lock.json).

При проверке каждого носителя временно снимайте остальные. Записанные из одного
образа системы имеют одинаковые UUID файловых систем и PARTUUID; при нескольких
подключённых копиях одного образа загрузчик и Linux могут выбрать разные носители.

После входа в систему сведения о фактической конфигурации можно получить так:

```sh
cat /etc/os-release
uname -r
cat /proc/cmdline
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS,MODEL
findmnt /
```

## Android на UFS

Модель `TOSHIBA THGJFCT2T84BAKCB rev 0100` сообщает версию UFS `0x0300`.
Для этой конфигурации нужен [исправленный XBL](xbl-ufs30.md) в SPI и UFS.
UFS содержит несколько LUN; имя `/dev/sda` относится к одному логическому
устройству, а не описывает всю конфигурацию накопителя.

Установка и проверка результата: [Android на UFS](../guides/android-ufs.md).
Размер раздела userdata и размер файловой системы `/data` различаются;
подробности приведены в том же руководстве.
