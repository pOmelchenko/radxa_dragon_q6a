# Waveshare 3.5inch DSI LCD (H) на Dragon Q6A

Эксперимент для Radxa OS (Linux), платы Q6A V1.21 и дисплея Waveshare
**SKU 33087**. Режим 35H задаёт 480×800 при 60 Гц, RGB888, одну линию DSI
и pixel clock 33,6 МГц. Контроллер касаний Goodix GT911 находится на I²C13.
Сборка модуля arm64 и применение оверлея к штатному DTB проверены для
`6.18.2-3-qcom` и `7.0.11-7-qcom`. На Q6A с ядром `7.0.11-7-qcom`
экран показал логин, затем стал циклически показывать изображение, полосы и чёрный
экран. Во время сбоя DRM показывал активный режим 480×800 при 60 Гц,
а дерево частот — 33,6 МГц для pixel и 100,8 МГц для byte (806,4 Мбит/с на D0).
GT911 ответил на I²C13 по адресу `0x5d` идентификатором `911`. Устойчивое
изображение, события касания и холодный старт ещё требуют проверки на плате.

## Подключение

Подключайте при выключенном питании через переходник **J10 (39 контактов,
шаг 0,3 мм) → Raspberry Pi DISPLAY (15 контактов)**. Перед включением
сверьте нумерацию и прозвоните переходник. 15-контактные разъёмы на самой
Q6A предназначены для камер. Контакты ниже пронумерованы со стороны
соответствующего разъёма, ориентация шлейфа зависит от переходника.

| Waveshare 15 pin | Сигнал | Q6A J10 по схеме V1.21 |
| --- | --- | --- |
| 1, 4, 7, 10, 13 | GND | Общая земля, например 6, 9, 12, 15, 28 |
| 2, 3 | D1−, D1+ | 10, 11 (пара выведена на разъём, профиль 35H её не использует) |
| 5, 6 | CLK−, CLK+ | 13, 14 |
| 8, 9 | D0−, D0+ | 7, 8 |
| 11, 12 | SCL, SDA | 27, 26 (TP_SCL, TP_SDA, сторона 3,3 В преобразователя U8) |
| 14, 15 | 3,3 В | Например, 30 и 31, оба на VCC_3V3_LCD |

GPIO80 включает питание модуля через U14. По данным Waveshare, потребление
составляет 180 мА при 3,3 В. Контакты J10 для 1,8 В и LED± оставьте
свободными. В 15-pin разъёме нет отдельных INT и RESET. Штатный драйвер
Goodix в обоих ядрах умеет опрашивать контроллер по I²C без IRQ. Управление
яркостью производитель для этой модели не заявляет.

## Установка из ветки

Скопируйте весь каталог [waveshare-35h](../../tools/target/linux/waveshare-35h)
по SFTP в домашний каталог на Q6A. Из SSH-сеанса на **плате** выполните одну команду.

```sh
sudo python3 ~/waveshare-35h/install.py
```

Если на компьютере есть OpenSSH, копирование и установку можно запустить
из корня репозитория одной командой. Подставьте своё SSH-имя или адрес платы.

```sh
sbc=radxa@dragon-q6a.local
scp -r tools/target/linux/waveshare-35h "$sbc:" && ssh -t "$sbc" 'sudo python3 ~/waveshare-35h/install.py'
```

Скрипт определяет версию работающего ядра, при необходимости устанавливает
инструменты и соответствующие заголовки через APT, собирает модуль и DTBO.
Он проверяет `vermagic`, совместимость панели и применимость полного списка
оверлеев к DTB текущего ядра. Затем устанавливает модуль, обновляет его индекс
и создаёт отдельный пункт **Waveshare 35H (auto)**. Для сборки нужны доступные
заголовки именно текущего ядра.

За основу берётся `/boot/efi/loader/entries/<entry-token>-<uname -r>.conf`.
Когда файл токена отсутствует, скрипт ищет штатный пункт `RadxaOS-<uname -r>.conf`.
Если рабочая система загружена с другой записи, укажите её через
`--entry /boot/efi/loader/entries/имя.conf`. Параметры загрузки и порядок
оверлеев камер копируются из этой записи. Оверлеи BTT TFT50, штатных DSI-дисплеев
Radxa и Raspberry Pi 7-inch исключаются из пробного пункта. Если другой
оверлей объявляет DSI или GPIO80 своим эксклюзивным ресурсом, установка
остановится с указанием его файла.

**Для готового архива** распакуйте его на плате и выполните из каталога
с `SHA256SUMS` и `install.py`.

```sh
sha256sum -c SHA256SUMS && sudo python3 ./install.py --prebuilt "$PWD/artifacts/waveshare-35h"
```

Этот режим использует общий DTBO и модуль из подкаталога с именем работающего
ядра. Модуль нужен для публикации режима 35H в DRM. В ядре Radxa 6.18.2-3
отсутствует привязка `panel-dsi`, а в 7.0.11-7 `panel_simple_dsi_probe()`
разбирает параметры в отдельный дескриптор, на который `panel->desc` затем
не указывает. Драйвер Goodix входит в оба пакета ядра.

## Пробная загрузка и возврат

После сообщения `Installed …` выключите Q6A, обесточьте плату для подключения
шлейфа и при включении выберите **Waveshare 35H (auto)** в меню embloader через UART.
Для возврата выберите прежнюю запись. Установщик выводит её имя.
Пробная запись находится в `/boot/efi/loader/entries/waveshare-35h-auto-<uname -r>.conf`.
После обновления ядра повторите установку для его версии.

## Проверка циклического мигания

Если изображение сменяется полосами и чёрным экраном, установите пробный
профиль из обновлённого каталога и выберите **Waveshare 35H (sync-pulse)**
в меню embloader при следующей загрузке.

```sh
sudo python3 ~/waveshare-35h/install.py --sync-pulse
```

У профилей одинаковые тайминги, одна линия RGB888 и общий оверлей с GT911
на `0x5d`. Пункт **(auto)** использует sync-event. Пункт **(sync-pulse)**
включает non-burst sync-pulse и пакеты конца горизонтальной синхронизации
(HSE) параметром модуля в своей загрузочной записи. Это проверка гипотезы:
драйвер VC4 на Raspberry Pi задаёт конец импульсов в видеорежиме, а драйвер
Qualcomm выбирает режим и HSE по флагам панели.

```sh
cat /sys/module/panel_waveshare_35h/parameters/sync_pulse
sudo journalctl -b -k --no-pager | grep -E 'DSI video:|Goodix-TS'
```

Для пробного профиля ожидаются `Y` и строка `DSI video: sync-pulse + HSE`.
Сравните видимое поведение с пунктом **(auto)** на том же подключении.

## Проверка на плате

```sh
for d in /sys/class/drm/card*-DSI-*; do
    [ -d "$d" ] && cat "$d/status" "$d/modes"
done
sudo journalctl -b -k | grep -iE 'waveshare|goodix|ae94000|dsi'
ls -l /sys/bus/i2c/devices/13-005d/driver
sudo evtest
```

Ожидаются режим `480x800`, устойчивое изображение, а в `evtest` у
`Goodix Capacitive TouchScreen` — касания и отпускания по четырём углам.
Проверьте их после холодного включения. При необходимости установите
`evtest` одноимённым пакетом.

Общий DTBO производителя содержит варианты для `0x14` и `0x5d`.
На проверенной панели чтение четырёх байтов регистра `0x8140` по адресу
`0x5d` дало `39 31 31 00`, а обращение к `0x14` завершилось ошибкой `-6`.
После привязки драйвера работу сенсора проверяйте через `evtest`.
