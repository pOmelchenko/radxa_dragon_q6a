# InnoMaker IMX296 Mono на Radxa Dragon Q6A

На Dragon Q6A V1.21 с Ubuntu 24.04.5 LTS и ядром `7.0.11-7-qcom` модуль **InnoMaker CAM-IMX296Mono-GS** через **CAM1/J14 и Radxa AC008** дал первый кадр 1456 × 1088 в формате `Y10P` (монохромный упакованный RAW10). Проверка охватывает захват одного кадра. Частота 60 кадров/с, внешний триггер и захват с IMX296 на CAM2/CAM3 требуют отдельных испытаний.

В журнале платы после перезагрузки список ожидания `qcom-camss` пуст. При включённых IMX296 на CAM1 и AR0234 на CAM2 скрипт выбрал маршрут `imx296 16-001a → msm_csiphy0 → msm_csid0 → msm_vfe0_rdi0` и получил кадр через `/dev/video0`. Шаг строки составил 1824 байта, размер сохранённого RAW — 1 984 512 байт. Для следующего запуска скрипт определяет номера устройств заново.

## Установка на Q6A

Скопируйте каталог `tools/target/linux/imx296` **целиком** на плату, например в `~/q6a-imx296`. Подойдут флешка, SCP или уже скачанный на плату репозиторий. Для получения ветки используйте `git clone --branch camera/imx296-cam2 https://github.com/pOmelchenko/radxa_dragon_q6a.git`.

В терминале **Q6A** перейдите в каталог комплекта и запустите установщик. Для CAM1/J14:

```bash
cd ~/q6a-imx296
sudo python3 install.py --port cam1
```

После клонирования на самой плате каталогом комплекта будет `radxa_dragon_q6a/tools/target/linux/imx296`. Для другого разъёма используйте `--port cam2` или `--port cam3` при установке и захвате.

| Что настроено на выбранном порту | Что сделает установщик |
| --- | --- |
| Свободен | Включит IMX296 сразу. |
| Уже включена IMX296 | Проверит маршрут. Повторный запуск допустим и до перезагрузки. |
| Другая камера со своим оверлеем | Покажет порт, модель и файл прежней камеры. Введите `да` для замены. Enter отменяет замену. |
| Камера встроена в базовый DTB или удаление её профиля затрагивает другое устройство | Остановится до записи конфигурации и укажет причину. |

Для установки с заранее подтверждённой заменой выполните на плате `sudo python3 install.py --port cam1 --replace`. При запуске без терминала этот флаг нужен только для замены. В обоих режимах установщик проверяет итоговый DTB.

Если нужно переставить камеру, выключите плату, обесточьте её, подключите IMX296 к выбранному порту и включите питание. Для CAM1 используйте AC008. Если IMX296 уже подключена и установщик сообщает об изменении конфигурации, достаточно обычной перезагрузки (`sudo reboot`). После загрузки выполните на Q6A:

```bash
cd ~/q6a-imx296
python3 capture.py --port cam1
```

Скрипт напечатает путь к каталогу с `frame.raw` и `preview.pgm`. На уже настроенной плате, где установщик сообщил о доступности камеры, захват можно запускать сразу.

### Доставка и запуск по SSH

С Mac или Linux эти же шаги установки можно выполнить одной командой из корня ветки:

```bash
sh tools/target/linux/imx296/deploy.sh "$Q6A" cam1
```

`Q6A` содержит SSH-адрес платы. По умолчанию используется `radxa@radxa-dragon-q6a.local`. Комплект будет скопирован в `~/q6a-imx296`, затем при замене камеры установщик задаст тот же вопрос в терминале SSH. Для заранее подтверждённой замены добавьте `--replace` последним аргументом. Предыдущие снимки сохраняются.

## Что меняется на плате

- Установщик работает с существующей записью EFI текущего ядра и добавляет в неё оверлей выбранного разъёма. Ядро, initramfs, параметры запуска и порядок остальных оверлеев сохраняются. Уже выбранная пользовательская запись и её базовый DTB также сохраняются. Для embloader установщик сам записывает идентификатор без суффикса `.conf`.
- Перед записью он применяет итоговый список оверлеев к DTB во временном каталоге, проверяет двустороннюю связь сенсора с CSIPHY, а также наличие, `compatible` и доступность узлов уже привязанных устройств I²C, SPI и MIPI DSI. Для соседних CSI-портов сравниваются связи сенсоров с CSIPHY и параметры endpoint до и после замены.
- При подтверждённой замене профиль IMX296 занимает место прежнего оверлея в списке загрузки. Прежний файл из каталога `dtbo` получает суффикс `.disabled` для rsetup. Если файл используют другие загрузочные записи, их ссылки переводятся на побайтовую копию в `imx296-saved-overlays/`. Общий пул памяти CMA, который поставлялся вместе с прежней камерой, сохраняет свой размер.
- Профили остальных камер, дисплея и тачскрина сохраняются, в том числе при ошибке probe на соседнем порту. На проверенной плате работала AR0234 на CAM2, были включены оба оверлея BTT, а CAM3 был свободен. Если в исходной конфигурации объявлена камера, которая не отвечает, CAMSS может ждать её перед созданием связей. Список ожидаемых устройств приведён в разделе диагностики.
- Требуемые утилиты устанавливаются через APT по необходимости. Модули `i2c-qcom-cci`, `imx296` и `qcom_camss` загружаются при установке и добавляются в `/etc/modules-load.d/q6a-imx296.conf`. На ядре без драйвера IMX296 установка остановится до записи в EFI.
- Перед первым изменением существующего файла конфигурации создаётся копия с суффиксом `.before-imx296`. Установщик не перезагружает плату сам. Для ручного возврата прежней записи после замены вначале восстановите исходное имя прежнего DTBO из копии `.dtbo.disabled`. Файлы `.before-imx296` содержат состояние до первого изменения соответствующего файла. После обновления ядра повторите команду установки для новой версии.

## Полученные файлы

Скрипт печатает выбранные media- и video-устройства и каталог `imx296-…`. В `frame.raw` сохраняется упакованный RAW10 со штатным шагом строки, а в `preview.pgm` — 8-битное монохромное изображение без выравнивания. Скрипт ищет свободную пару CSID/VFE с RDI0 и не отключает каналы других камер. Если подходящего маршрута нет, он сообщает об этом до настройки форматов.

Чтобы посмотреть превью на Mac с ImageMagick, подставьте в `shot` имя каталога из вывода скрипта и выполните на Mac:

```bash
shot=imx296-_sma54ys
scp "${Q6A}:q6a-imx296/$shot/preview.pgm" "$HOME/Downloads/$shot.pgm" &&
    magick "$HOME/Downloads/$shot.pgm" "$HOME/Downloads/$shot.png" &&
    open "$HOME/Downloads/$shot.png"
```

После снимка скрипт освобождает только те связи media graph, которые сам включил. Устойчивые 60 кадров/с требуют отдельной проверки по меткам времени последовательных кадров. Для проверки внешнего запуска отдельно понадобятся ревизия модуля, схема его разъёма и источник импульсов. У производителя есть свои [инструкции по trigger/strobe](https://github.com/INNO-MAKER/cam-imx296raw-trigger). Номера I²C-шин и GPIO из примеров Raspberry Pi на Q6A отличаются.

## Выбрать разъём

По умолчанию установщик и захват используют **CAM1/J14 с Radxa AC008**. Каждый профиль включает один разъём. Для свободного режима оставьте внешний триггер и строб неподключёнными. Подключайте шлейф при обесточенной плате. Обозначения J14, J16 и J7 даны по [монтажному чертежу Q6A V1.21](../vendor/radxa-q6a-components-v1.21.pdf).

| Параметр | Разъём платы | Кабель к InnoMaker | Шина сенсора | Приёмник | Включение модуля |
| --- | --- | --- | --- | --- | --- |
| **`--port cam1`** | **J14, 31P / 0,3 мм** | **Radxa AC008, 31P → 15P, контакты на одной стороне** | `cci0_i2c0` | `msm_csiphy0` | GPIO36, J14 pin 23 через AC008 |
| `--port cam2` | J16, 15P / 1 мм | 15P → 15P, контакты на противоположных сторонах | `cci1_i2c0` | `msm_csiphy2` | GPIO77, J16 pin 11 |
| `--port cam3` | J7, 15P / 1 мм | 15P → 15P, контакты на противоположных сторонах | `cci1_i2c1` | `msm_csiphy3` | GPIO78, J7 pin 11 |

### CAM1 с кабелем AC008

Вставьте конец **31P / 0,3 мм** в J14 на Q6A, конец **15P / 1,0 мм** — в InnoMaker. В схеме AC008 V1.1 микросхема **U90110 (UM3204H)** согласует уровни **1,8 В ↔ 3,3 В** для SDA, SCL и разрешения питания. Сигнал `CAM0_POWER_EN` приходит с GPIO36 через J14 pin 23. J14 pin 27 (`CAM0_RESET_N`, GPIO20) в этой цепи не используется. Внешний преобразователь уровней для данной схемы не требуется. [Страница AC008](https://radxa.com/products/accessories/fpc-adapter-cable-ac008/), [схема AC008 V1.1](https://dl.radxa.com/accessories/fpc-cable/008/radxa_fpc_cable_008_schematic_v1.1.pdf), [схема Q6A V1.21, лист CAM](../vendor/radxa-q6a-schematic-v1.21.pdf)

| Сигнал | Q6A J14 | AC008 J5003, сторона 15P | Разъём камеры по InnoMaker |
| --- | --- | --- | --- |
| CSI DATA0 − / + | 14 / 15 | 14 / 13 | 2 / 3 |
| CSI CLK − / + | 17 / 18 | 8 / 7 | 8 / 9 |
| Power Enable | 23 | 5 | 11 (CAM_IO0) |
| I²C SCL / SDA | 24 / 25 | 3 / 2 | 13 / 14 |
| Питание 3,3 В | 28, 29 | 1 | 15 |

На стороне 15P в двух схемах номера отсчитываются с разных концов. В таблице столбцы сопоставлены по сигналам. Для всех профилей адрес IMX296 равен `0x1a`, используется одна линия данных CSI-2. Частота генератора модуля 54 МГц принята по конфигурации Raspberry Pi, измерения на данном экземпляре нет. На AC008 V1.1 резистор R95170 в цепи внешнего MCLK отмечен NC. [Руководство InnoMaker, раздел 2.1](https://www.inno-maker.com/wp-content/uploads/2021/05/CAM-IMX296RAW-UserManual-V2.0.pdf), [оверлей IMX296 для Pi](https://github.com/raspberrypi/linux/blob/rpi-6.12.y/arch/arm/boot/dts/overlays/imx296-overlay.dts)

Маршрутизация CCI и CSIPHY сверена с оверлеями Radxa для [CAM1](https://github.com/radxa-pkg/radxa-overlays/blob/main/arch/arm64/boot/dts/qcom/overlays/qcs6490-radxa-dragon-q6a-cam1-radxa-camera-4k.dtso), [CAM2](https://github.com/radxa-pkg/radxa-overlays/blob/main/arch/arm64/boot/dts/qcom/overlays/qcs6490-radxa-dragon-q6a-cam2-radxa-camera-8m-219.dtso) и [CAM3](https://github.com/radxa-pkg/radxa-overlays/blob/main/arch/arm64/boot/dts/qcom/overlays/qcs6490-radxa-dragon-q6a-cam3-radxa-camera-8m-219.dtso).

## Если кадра нет

На плате проверьте сообщения сенсора и список устройств, которых ждёт CAMSS:

```bash
sudo journalctl -k -b --no-pager | grep -Ei 'imx296|ar0234|camss'
sudo cat /sys/kernel/debug/v4l2-async/pending_async_subdevices
```

Сообщение `found IMX296LL` подтверждает чтение модели сенсора. Если у сенсора в media graph `0 link`, строка под `qcom-camss` в debugfs указывает на ожидаемый endpoint. Для AR0234 на контроллере `cci@ac4b000` подшина `i2c-bus@0` соответствует CAM2, `i2c-bus@1` — CAM3. Номер Linux-адаптера может меняться. Сверьте время последней загрузки (`uptime -s`) и порт.

Реализация сенсора и таблицы форматов захвата проверялись по исходникам [драйвера IMX296](https://github.com/radxa/kernel/blob/a50eb5b71984bd82b49cd5d31b1e2eb5505c6512/drivers/media/i2c/imx296.c) и [CAMSS VFE](https://github.com/radxa/kernel/blob/a50eb5b71984bd82b49cd5d31b1e2eb5505c6512/drivers/media/platform/qcom/camss/camss-vfe.c) для Radxa `7.0.11-7`.
