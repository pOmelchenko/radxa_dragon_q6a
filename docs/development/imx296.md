# InnoMaker IMX296 Mono на Radxa Dragon Q6A

Первый запуск одного модуля **CAM-IMX296Mono-GS (IMX296LLR)** на Dragon Q6A V1.21 с Radxa OS. На Ubuntu 24.04.5 LTS с ядром `7.0.11-7-qcom` и кабелем AC008 драйвер обнаружил IMX296LL на CAM1. Следующая проверка — один различимый монохромный кадр 1456 × 1088 в свободном режиме. Захват, 60 кадров/с и внешний запуск пока не подтверждены.

## Выбрать разъём

По умолчанию установщик и захват используют **CAM1/J14 с Radxa AC008**. Каждый профиль включает один разъём. Для свободного режима оставьте внешний триггер и строб неподключёнными. Подключайте шлейф при обесточенной плате. Обозначения J14, J16 и J7 даны по [монтажному чертежу Q6A V1.21](../vendor/radxa-q6a-components-v1.21.pdf).

| Параметр | Разъём платы | Кабель к InnoMaker | Шина сенсора | Приёмник | Включение модуля |
| --- | --- | --- | --- | --- | --- |
| **`--port cam1`** | **J14, 31P / 0,3 мм** | **Radxa AC008, 31P → 15P, контакты на одной стороне** | `cci0_i2c0` | `msm_csiphy0` | GPIO36, J14 pin 23 через AC008 |
| `--port cam2` | J16, 15P / 1 мм | 15P → 15P, контакты на противоположных сторонах | `cci1_i2c0` | `msm_csiphy2` | GPIO77, J16 pin 11 |
| `--port cam3` | J7, 15P / 1 мм | 15P → 15P, контакты на противоположных сторонах | `cci1_i2c1` | `msm_csiphy3` | GPIO78, J7 pin 11 |

### CAM1 с кабелем AC008

Вставьте конец **31P / 0,3 мм** в J14 на Q6A, конец **15P / 1,0 мм** — в InnoMaker. В схеме AC008 V1.1 микросхема **U90110 (UM3204H)** согласует уровни **1,8 В ↔ 3,3 В** для SDA, SCL и разрешения питания. Сигнал `CAM0_POWER_EN` приходит с GPIO36 через J14 pin 23. J14 pin 27 (`CAM0_RESET_N`, GPIO20) в этой цепи не используется. Внешний преобразователь уровней для данной схемы не требуется. [Страница AC008](https://radxa.com/products/accessories/fpc-adapter-cable-ac008/), [схема AC008 V1.1](https://dl.radxa.com/accessories/fpc-cable/008/radxa_fpc_cable_008_schematic_v1.1.pdf), [схема Q6A V1.21, лист CAM](../vendor/radxa-q6a-schematic-v1.21.pdf)

| Сигнал | Q6A J14 | AC008 J5003, сторона 15P | Разъём камеры по InnoMaker |
| --- | --- | --- | --- |
| CSI DATA0 − / + | 14 / 15 | 14 / 13 | 2 / 3 |
| CSI CLK − / + | 17 / 18 | 8 / 7 | 8 / 9 |
| Power Enable | 23 | 5 | 11 (CAM_IO0) |
| I²C SCL / SDA | 24 / 25 | 3 / 2 | 13 / 14 |
| Питание 3,3 В | 28, 29 | 1 | 15 |

На стороне 15P в двух схемах номера отсчитываются с разных концов. В таблице столбцы сопоставлены по сигналам. Для всех профилей адрес IMX296 равен `0x1a`, используется одна линия данных CSI-2. Частота генератора модуля 54 МГц принята по конфигурации Raspberry Pi, измерения на данном экземпляре нет. На AC008 V1.1 резистор R95170 в цепи внешнего MCLK отмечен NC. [Руководство InnoMaker, раздел 2.1](https://www.inno-maker.com/wp-content/uploads/2021/05/CAM-IMX296RAW-UserManual-V2.0.pdf), [оверлей IMX296 для Pi](https://github.com/raspberrypi/linux/blob/rpi-6.12.y/arch/arm/boot/dts/overlays/imx296-overlay.dts)

Маршрутизация CCI и CSIPHY сверена с оверлеями Radxa для [CAM1](https://github.com/radxa-pkg/radxa-overlays/blob/main/arch/arm64/boot/dts/qcom/overlays/qcs6490-radxa-dragon-q6a-cam1-radxa-camera-4k.dtso), [CAM2](https://github.com/radxa-pkg/radxa-overlays/blob/main/arch/arm64/boot/dts/qcom/overlays/qcs6490-radxa-dragon-q6a-cam2-radxa-camera-8m-219.dtso) и [CAM3](https://github.com/radxa-pkg/radxa-overlays/blob/main/arch/arm64/boot/dts/qcom/overlays/qcs6490-radxa-dragon-q6a-cam3-radxa-camera-8m-219.dtso).

## Перенести комплект с Mac или Linux на SBC

На компьютере скачайте ветку в отдельный каталог. В `Q6A` укажите свой рабочий SSH-адрес. Подойдёт IP платы или имя хоста, которое у вас разрешается. При первом запуске клонируйте ветку. Если каталог уже есть, перейдите в него и выполните `git pull --ff-only origin camera/imx296-cam2`. Затем скопируйте весь комплект, включая общий файл DTSI и таблицу разъёмов.

```bash
git clone --depth 1 --branch camera/imx296-cam2 \
  https://github.com/pOmelchenko/radxa_dragon_q6a.git radxa-q6a-camera
cd radxa-q6a-camera
Q6A=radxa@radxa-dragon-q6a.local
ssh "$Q6A" 'mkdir -p ~/q6a-imx296'
scp tools/target/linux/imx296/*.py tools/target/linux/imx296/*.dts tools/target/linux/imx296/*.dtsi \
    "${Q6A}:q6a-imx296/"
ssh -t "$Q6A" 'cd ~/q6a-imx296 && sudo python3 install.py --register-rsetup && sudo rsetup'
```

Последняя команда запускает установщик на плате. Он проверяет модель, смонтированный EFI-раздел и драйверы текущего ядра. Если утилит не хватает, устанавливает пакеты `cpp`, `device-tree-compiler`, `v4l-utils` и `kmod` по необходимости. Для `7.0.11-7-qcom` модуль сенсора уже входит в пакет ядра. Если `modinfo` сообщает `Module imx296 not found`, проверьте `uname -r` и `grep VIDEO_IMX296 /boot/config-"$(uname -r)"`. Для штатного `6.18.2-3-qcom` см. [обновление Radxa OS](../guides/linux-update.md).

### Выбрать оверлей по SSH

В **Overlays → Manage overlays** появятся три строки **Enable InnoMaker IMX296 Mono on CAM1/CAM2/CAM3**, по одной на разъём. Установщик помещает новые DTBO в каталог текущего ядра с суффиксом `.disabled`. При повторной регистрации он сохраняет сделанный выбор.

1. Для J14 отметьте пробелом **Enable InnoMaker IMX296 Mono on CAM1**. Оставьте остальные профили камер на CAM1 выключенными.
2. Оставьте отмеченными оверлеи дисплея и подключённых работающих камер. Снимите отметки камер, которые отсутствуют или пока не отвечают. Например, если AR0234 на CAM2 читает chip ID, а на CAM3 получает `-ENXIO`, оставьте AR0234 на CAM2 и отключите AR0234 на CAM3.
3. Сохраните выбор клавишей Enter и выйдите из rsetup. Если обычная запись Radxa OS выбрана по умолчанию, выполните с компьютера `ssh -t "$Q6A" 'sudo reboot'` и дождитесь возвращения SSH. Вручную выбирать запись во время загрузки для этого способа не требуется.

Перед перезагрузкой можно сверить результат на плате. В первой строке ожидается штатная запись текущего ядра, а в `devicetree-overlay` этой записи — файл `q6a-cam1-innomaker-imx296.dtbo` и имена остальных отмеченных оверлеев. Если запись выбрана другая, сначала сверьте, какие настройки использует плата при обычном запуске.

```bash
sudo grep '^default ' /boot/efi/loader/loader.conf
sudo grep '^devicetree-overlay ' "/boot/efi/loader/entries/$(cat /etc/kernel/entry-token)-$(uname -r).conf"
```

После обновления ядра повторите регистрацию в каталоге новой версии и проверьте выбор. Затем перейдите к [проверке сенсора и захвату](#проверить-сенсор-и-получить-первый-кадр).

## Отдельная тестовая запись embloader

Для эксперимента с ручным выбором при старте выполните на Q6A `cd ~/q6a-imx296 && sudo python3 install.py --port cam1`. По умолчанию основой служит `/boot/efi/loader/entries/RadxaOS-$(uname -r).conf`. Чтобы включить оверлеи из другой загрузочной записи, например рабочего дисплея, укажите её явно:

```bash
sudo ls /boot/efi/loader/entries/
cd ~/q6a-imx296
sudo python3 install.py --port cam1 --entry /boot/efi/loader/entries/Q6A-BTT-TFT50-7-test.conf
```

Установщик применяет к DTB выбранной записи её оверлеи в исходном порядке, затем оверлей IMX296. Если выбранный порт уже занят, установка остановится до записи в EFI. Итоговый DTB с проверенными ссылками между сенсором и выбранным CSIPHY получает отдельное имя. Копия записи загрузки ссылается на него и сохраняет ядро, initramfs и параметры исходной записи.

### Загрузка тестовой записи

Для CAM2 или CAM3 повторите команду установщика с `--port cam2` или `--port cam3`. Каждая пара «порт + исходная запись» получает свой пункт загрузки. Для уже установленного прежней версией CAM2 явно укажите `--port cam2` при захвате.

Запишите название из строки **«Выберите в embloader»**, подключите камеру к выбранному разъёму при выключенном питании и при следующем старте выберите **InnoMaker IMX296 Mono on CAM1 (…)** для J14 в меню embloader через UART. Для доступа к консоли см. [аппаратный справочник](../reference/hardware.md). При возврате выберите исходную запись, имя которой напечатал установщик. Установка сама не перезагружает плату. После обновления ядра запустите установщик ещё раз для новой версии.

## Проверить сенсор и получить первый кадр

После загрузки подключитесь по SSH. Для CAM1 выполните на плате следующий блок. Для CAM2 задайте `bus_symbol=cci1_i2c0`, для CAM3 — `bus_symbol=cci1_i2c1`.

```bash
bus_symbol=cci0_i2c0
bus=$(tr -d '\0' <"/proc/device-tree/__symbols__/$bus_symbol")
tr -d '\0' <"/proc/device-tree$bus/camera@1a/compatible"
echo
sudo modprobe i2c-qcom-cci
sudo modprobe imx296
sudo modprobe qcom_camss
sudo journalctl -k -b --no-pager | grep -Ei 'imx296|camss|csiphy|ac4a000|ac4b000|acb3000'
for m in /dev/media*; do
    [ -c "$m" ] && media-ctl -d "$m" -p
done
```

Ожидаемые признаки по порядку:

1. В загруженном DT присутствует `sony,imx296`.
2. Драйвер прочитал регистр модели по I²C и сообщил `found IMX296LL`. Один узел `camera@1a` в DT ещё не подтверждает ответ камеры. Оверлей использует общий compatible, чтобы драйвер проверял модель.
3. В одном media graph от `imx296 <шина>-001a` идёт включённая связь к приёмнику из таблицы (для CAM1 — `msm_csiphy0`). Остановите другие клиенты камеры, затем выполните на плате:

```bash
cd ~/q6a-imx296
python3 capture.py --port cam1
```

Задайте тот же порт, что и при установке. Скрипт находит media-устройство по этой связи, настраивает путь через CSID0 и VFE0/RDI0, запрашивает `Y10P`, проверяет согласованные размер, формат, шаг строки и длину полученного кадра. Результат появится в новом каталоге `imx296-…` текущей директории. `frame.raw` содержит 10-битный упакованный кадр с выравниванием строк, `preview.pgm` — старшие 8 бит каждого пикселя без выравнивания. Откройте PGM и проверьте, что виден объект перед камерой. Для сравнения можно переместить объект и повторить команду. Для доступа нужны права на устройства группы `video`.

После первого кадра скрипт оставляет маршрут настроенным и печатает путь к capture-устройству. Для проверки частоты подставьте **этот** путь вместо `/dev/videoN`:

```bash
timeout 15s v4l2-ctl -d /dev/videoN --stream-mmap=4 --stream-count=120 --stream-to=/dev/null --verbose
```

Успех на 60 кадрах/с подтверждается по интервалам меток времени около 16,7 мс, последовательным номерам и отсутствию ошибок CSI на плате. Для проверки внешнего запуска отдельно понадобятся ревизия модуля, схема его разъёма и источник импульсов. У производителя есть свои [инструкции по trigger/strobe](https://github.com/INNO-MAKER/cam-imx296raw-trigger). Номера I²C-шин и GPIO из примеров Raspberry Pi на Q6A отличаются.

## Если кадра нет

| Наблюдение | Что проверить |
| --- | --- |
| Нет пути `camera@1a` в `/proc/device-tree` | Для rsetup проверьте выбранный разъём и строку `devicetree-overlay` штатной записи. Для отдельного DTB сверьте выбранную запись embloader с выводом установщика. |
| Узел есть, регистрации IMX296LL нет | Сохраните журнал probe. Проверьте выбранный разъём, ориентацию шлейфа, питание и CAM_IO0. Ошибка чтения идентификатора требует проверки I²C и ревизии модуля. |
| Есть IMX296LL, но у сенсоров в графе `0 link` | CAMSS связывает сенсоры с CSIPHY, когда зарегистрировались все ожидаемые камеры. Найдите ошибки probe других камер в журнале. Сопоставьте устройство, например `20-0010`, с разъёмом через `readlink -f /sys/bus/i2c/devices/20-0010/of_node`. Для CCI `ac4b000` шина `i2c-bus@0` соответствует CAM2, а `i2c-bus@1` — CAM3. Если один сенсор недоступен, отключите его оверлей и перезагрузитесь. [Исходный код CAMSS этой версии](https://github.com/radxa/kernel/blob/a50eb5b71984bd82b49cd5d31b1e2eb5505c6512/drivers/media/platform/qcom/camss/camss.c) |
| Есть граф, захват завершился по тайм-ауту или с ошибкой формата | Сохраните полный вывод скрипта, `media-ctl -p` для найденного устройства и журнал ядра после попытки. Проверьте свободный режим, одну линию RAW10 и что другие клиенты освободили маршрут. |

Реализация сенсора и таблицы форматов захвата проверялись по исходникам [драйвера IMX296](https://github.com/radxa/kernel/blob/a50eb5b71984bd82b49cd5d31b1e2eb5505c6512/drivers/media/i2c/imx296.c) и [CAMSS VFE](https://github.com/radxa/kernel/blob/a50eb5b71984bd82b49cd5d31b1e2eb5505c6512/drivers/media/platform/qcom/camss/camss-vfe.c) для Radxa `7.0.11-7`.
