# InnoMaker IMX296 Mono на CAM2/J16

Первый запуск одного модуля **CAM-IMX296Mono-GS (IMX296LLR)** на Dragon Q6A V1.21 с Radxa OS. Целевая система — Ubuntu 24.04.5 LTS, `7.0.11-7-qcom`. Получить нужно один различимый монохромный кадр 1456 × 1088 в свободном режиме. Захват на плате, частота 60 кадров/с и внешний запуск пока не проверены.

## Подключение

На **обесточенной** Q6A подключите модуль к **J16 (CAM2)** шлейфом Raspberry Pi **15 → 15 контактов, шаг 1 мм, контакты на противоположных сторонах**. Сверьте J16 по [монтажному чертежу V1.21](../vendor/radxa-q6a-components-v1.21.pdf). На первом запуске вход триггера и выход строба оставьте свободными. Второй похожий разъём J7 подключён к другой шине CCI и другому CSIPHY.

| Сигнал | Соединение для этого модуля |
| --- | --- |
| Питание и разрешение питания | J16 pin 15 — 3,3 В. Pin 11 — CAM_IO0, активный высокий уровень от TLMM GPIO77 через преобразователь платы. Включение модуля и задержка 500 мс описаны в DT. |
| I²C | Pins 13/14 — SCL/SDA, CCI1 master 0, 7-битный адрес сенсора `0x1a`. Номер Linux-адаптера назначается при загрузке. |
| CSI-2 | Одна линия DATA0 (pins 2/3) и тактовая пара (8/9), приёмник CSIPHY2. Нумерация линий в DT у сенсора и Qualcomm различается. |
| Опорный такт | В руководстве InnoMaker pin 12 — CAM_IO1/LED. Оверлей описывает фиксированные 54 МГц по эталонной конфигурации Pi. Это предположение о генераторе модуля, частота на данном экземпляре не измерена. На Q6A R358 в цепи CAM_MCLK2 по схеме не установлен. |

Источники — [руководство InnoMaker, раздел 2.1](https://www.inno-maker.com/wp-content/uploads/2021/05/CAM-IMX296RAW-UserManual-V2.0.pdf), [схема Q6A, лист CAM](../vendor/radxa-q6a-schematic-v1.21.pdf), [рекомендация Radxa для 15-контактного шлейфа](https://docs.radxa.com/en/dragon/q6a/accessories/camera-8m-219), [маршрутизация CAM2 у Radxa](https://github.com/radxa-pkg/radxa-overlays/blob/main/arch/arm64/boot/dts/qcom/overlays/qcs6490-radxa-dragon-q6a-cam2-radxa-camera-8m-219.dtso), [параметры модуля у Raspberry Pi](https://github.com/raspberrypi/linux/blob/rpi-6.12.y/arch/arm/boot/dts/overlays/imx296-overlay.dts).

## Перенести комплект с Mac или Linux на SBC

На компьютере скачайте ветку в отдельный каталог. В `Q6A` укажите свой рабочий SSH-адрес. Подойдёт IP платы или имя хоста, которое у вас разрешается. Для передачи нужны только установщик, исходник оверлея и скрипт захвата.

```bash
git clone --depth 1 --branch camera/imx296-cam2 \
  https://github.com/pOmelchenko/radxa_dragon_q6a.git radxa-q6a-camera
cd radxa-q6a-camera
Q6A=radxa@radxa-dragon-q6a.local
ssh "$Q6A" 'mkdir -p ~/q6a-imx296'
scp tools/target/linux/imx296/{install.py,capture.py,q6a-cam2-innomaker-imx296.dts} \
    "${Q6A}:q6a-imx296/"
ssh -t "$Q6A" 'cd ~/q6a-imx296 && sudo python3 install.py'
```

Последняя команда запускает установщик на плате. Он проверяет модель, смонтированный EFI-раздел и драйверы текущего ядра. Если утилит не хватает, устанавливает пакеты `device-tree-compiler`, `v4l-utils` и `kmod` по необходимости. Для `7.0.11-7-qcom` модуль сенсора уже входит в пакет ядра. Если `modinfo` сообщает `Module imx296 not found`, проверьте `uname -r` и `grep VIDEO_IMX296 /boot/config-"$(uname -r)"`. Для штатного `6.18.2-3-qcom` см. [обновление Radxa OS](../guides/linux-update.md).

По умолчанию основой служит `/boot/efi/loader/entries/RadxaOS-$(uname -r).conf`. Чтобы включить в эксперимент оверлеи из другой загрузочной записи, например рабочего дисплея, укажите её явно **вместо** последней команды выше. Пример для консоли Q6A, если такая запись есть:

```bash
sudo ls /boot/efi/loader/entries/
cd ~/q6a-imx296
sudo python3 install.py --entry /boot/efi/loader/entries/Q6A-BTT-TFT50-7-test.conf
```

Установщик применяет к DTB выбранной записи её оверлеи в исходном порядке, затем оверлей IMX296. Если CAM2 уже занят, установка остановится до записи в EFI. Итоговый DTB с проверенными ссылками между сенсором и CSIPHY2 получает отдельное имя. Копия записи загрузки ссылается на него и сохраняет ядро, initramfs и параметры исходной записи.

## Загрузить конфигурацию камеры

Запишите название из строки **«Выберите в embloader»**, подключите камеру к J16 при выключенном питании и при следующем старте выберите **InnoMaker IMX296 Mono on CAM2 (…)** в меню embloader через UART. Для доступа к консоли см. [аппаратный справочник](../reference/hardware.md). При возврате выберите исходную запись, имя которой напечатал установщик. Установка сама не перезагружает плату. После обновления ядра запустите установщик ещё раз для новой версии.

## Проверить сенсор и получить первый кадр

После загрузки снова подключитесь по SSH и выполните на Q6A:

```bash
tr -d '\0' </proc/device-tree/soc@0/cci@ac4b000/i2c-bus@0/camera@1a/compatible
echo
sudo modprobe i2c-qcom-cci
sudo modprobe imx296
sudo modprobe qcom_camss
sudo journalctl -k -b --no-pager | grep -Ei 'imx296|camss|csiphy|ac4b000|acb3000'
for m in /dev/media*; do
    [ -c "$m" ] && media-ctl -d "$m" -p
done
```

Ожидаемые признаки по порядку:

1. В загруженном DT присутствует `sony,imx296`.
2. Драйвер прочитал регистр модели по I²C и сообщил `found IMX296LL`. Один узел `camera@1a` в DT ещё не подтверждает ответ камеры. Оверлей использует общий compatible, чтобы драйвер проверял модель.
3. В одном media graph от `imx296 <шина>-001a` идёт включённая связь к `msm_csiphy2`. Остановите другие клиенты камеры, затем выполните на плате:

```bash
cd ~/q6a-imx296
python3 capture.py
```

Скрипт находит media-устройство по этой связи, настраивает путь через CSID0 и VFE0/RDI0, запрашивает `Y10P`, проверяет согласованные размер, формат, шаг строки и длину полученного кадра. Результат появится в новом каталоге `imx296-…` текущей директории. `frame.raw` содержит 10-битный упакованный кадр с выравниванием строк, `preview.pgm` — старшие 8 бит каждого пикселя без выравнивания. Откройте PGM и проверьте, что виден объект перед камерой. Для сравнения можно переместить объект и повторить команду. Для доступа нужны права на устройства группы `video`.

После первого кадра скрипт оставляет маршрут настроенным и печатает путь к capture-устройству. Для проверки частоты подставьте **этот** путь вместо `/dev/videoN`:

```bash
timeout 15s v4l2-ctl -d /dev/videoN --stream-mmap=4 --stream-count=120 --stream-to=/dev/null --verbose
```

Успех на 60 кадрах/с подтверждается по интервалам меток времени около 16,7 мс, последовательным номерам и отсутствию ошибок CSI на плате. Для проверки внешнего запуска отдельно понадобятся ревизия модуля, схема его разъёма и источник импульсов. У производителя есть свои [инструкции по trigger/strobe](https://github.com/INNO-MAKER/cam-imx296raw-trigger). Номера I²C-шин и GPIO из примеров Raspberry Pi на Q6A отличаются.

## Если кадра нет

| Наблюдение | Что проверить |
| --- | --- |
| Нет пути `camera@1a` в `/proc/device-tree` | Выбрана ли в embloader запись InnoMaker IMX296 для текущего ядра. Сверьте имя записи из вывода установщика. |
| Узел есть, регистрации IMX296LL нет | Сохраните журнал probe. Проверьте J16, ориентацию шлейфа, питание и CAM_IO0. Ошибка чтения идентификатора требует проверки I²C и ревизии модуля. |
| Есть IMX296LL, но нет связи с CSIPHY2 | Проверьте вывод `modprobe qcom_camss`, записи CAMSS в журнале и графы всех устройств `/dev/media*`. |
| Есть граф, захват завершился по тайм-ауту или с ошибкой формата | Сохраните полный вывод скрипта, `media-ctl -p` для найденного устройства и журнал ядра после попытки. Проверьте свободный режим, одну линию RAW10 и что другие клиенты освободили маршрут. |

Реализация сенсора и таблицы форматов захвата проверялись по исходникам [драйвера IMX296](https://github.com/radxa/kernel/blob/a50eb5b71984bd82b49cd5d31b1e2eb5505c6512/drivers/media/i2c/imx296.c) и [CAMSS VFE](https://github.com/radxa/kernel/blob/a50eb5b71984bd82b49cd5d31b1e2eb5505c6512/drivers/media/platform/qcom/camss/camss-vfe.c) для Radxa `7.0.11-7`.
