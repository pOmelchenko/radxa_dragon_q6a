# BTT Pi TFT50 V2.1 на Radxa Dragon Q6A

На Q6A с Radxa OS R2 / Ubuntu 24.04.5 LTS, NVMe и ядром
**`7.0.11-7-qcom`** проверены изображение **800×480**, подсветка,
нажатия, отпускания и точность координат TFT50 V2.1.
Владелец подтвердил изображение и корректную реакцию интерфейса на касания.

Питание и изображение проверены после перезагрузки. Автозагрузка модуля
с polling также проверена после перезагрузки, но окончательная правка
обработки пакетов проверена заменой модуля в работающей системе и затем
сохранена на диск. Повторной перезагрузки после этой последней правки
не было. Multitouch, suspend/resume и длительная работа не проверены.
[Полный результат и хеши](../reference/validation/btt-pi-tft50-v2.1-2026-10-15.json).

## Подключение и причина исправлений

Подключение, указанное владельцем: **39-контактный DSI Q6A → Radxa ROCK
5A/5B/5C/4C+ FPC Adapter Cable — 39-Pin to 15-Pin for Raspberry Pi 7-Inch
Display → BTT Pi TFT50 V2.1**. Маркировка переходника и ориентация контактов
не подтверждены фотографией; название сохранено со слов владельца.
Два 15-контактных разъёма Q6A относятся к камерам, а не к DSI.
Подключать и переставлять шлейф следует при отключённом питании платы.

| Часть | Исправление |
| --- | --- |
| Питание LCD | По схеме Q6A V1.21, печатные листы 6 и 31, TLMM GPIO80 управляет `LCD_VCC_EN` / U14 `SGM2578AAD` и шиной `VCC_3V3_LCD` на J10. Штатный оверлей её не включал. Отдельный GPIO hog удерживает GPIO80 в 1 с момента инициализации TLMM. Это номер GPIO SoC, не контакт 40-pin header. |
| Изображение | Используется схема panel/bridge/ATTiny из штатного оверлея Raspberry Pi 7-inch. В проверенной системе ATTiny — I2C13, `0x45`, тачскрин — `0x38`. |
| Касания | Из копии DTBO удалены `interrupts`, `interrupt-parent` и соответствующий fixup `tlmm`: штатный вариант назначал GPIO29. Для этого подключения используется polling 17 мс. |
| Пакеты касаний | Дополнительный патч учитывает число точек в `TD_STATUS` и исчезновение контактов; чтение всех слотов давало устаревшие данные и неверную реакцию. |

Источники: [сохранённая схема Q6A](../vendor/radxa-q6a-schematic-v1.21.pdf),
[драйвер, авторы и патчи](../../tools/dependencies/linux-tft50/README.md).
Другой оверлей или потребитель не должен занимать GPIO80 или тот же DSI.
Рецепт фиксирует включение штатной шины LCD; дополнительные провода питания
в исходной проверке отдельно не документировались.

## Подготовка на Q6A

Все команды ниже выполняются **в Linux самой Q6A**, из корня этого
репозитория. Рабочей установке, описанной выше, повторная установка не нужна.
Новые инструменты проверены сборкой на Q6A и тестами файловых изменений;
полная установка именно этими обёртками с последующим запуском ещё не проверена.

```sh
uname -r
sudo apt install --no-install-recommends python3 build-essential \
  device-tree-compiler kmod initramfs-tools-core "linux-headers-$(uname -r)"
```

Нужны заголовки именно `7.0.11-7-qcom`. При другом ядре или отсутствии
его заголовков сначала требуется отдельная адаптация; менять проверку
версии в скрипте для обхода этого условия не следует.

Проверить EFI-запись текущего ядра:

```sh
tft_kernel=$(uname -r)
tft_token=$(cat /etc/kernel/entry-token)
tft_entry="/boot/efi/loader/entries/${tft_token}-${tft_kernel}.conf"
sudo cat "$tft_entry"
```

В проверенной системе это `RadxaOS-7.0.11-7-qcom.conf`, а пути DTB/DTBO
начинаются с `/RadxaOS/7.0.11-7-qcom/`. Сверьте `linux`, `devicetree`,
`options` и список `devicetree-overlay` со своей конфигурацией.
Установщик принимает явный путь к записи; он не выбирает другой носитель
или пункт загрузки автоматически.

Штатный DTBO нужен как **вход сборки**. Найти имеющуюся копию:

```sh
sudo find /boot -name 'qcs6490-radxa-dragon-q6a-raspberry-pi-7-inch-touchscreen.dtbo*'
```

Выберите один файл из найденных. В проверенной системе доступна следующая
копия; замените путь, если ваша находится в каталоге EFI:

```sh
tft_stock=/boot/dtbo/qcs6490-radxa-dragon-q6a-raspberry-pi-7-inch-touchscreen.dtbo.disabled
mkdir -p artifacts/tft50-input
sudo install -m 0644 "$tft_stock" artifacts/tft50-input/rpi7.dtbo
sha256sum artifacts/tft50-input/rpi7.dtbo
```

Ожидаемый SHA-256:
`10ed0dbc17fbc170a455fc30e6a5c07d1b666d90186fff6b421bc5a248cd8b68`.
Сборка остановится при несовпадении. `/boot/dtbo` в этой системе — источник
копии, **не активный каталог оверлеев UEFI**. Включать штатный оверлей через
`rsetup` перед установкой не требуется.

## Сборка и установка

```sh
python3 tools/target/linux/tft50/build.py \
  --stock-overlay artifacts/tft50-input/rpi7.dtbo \
  --output artifacts/tft50-7.0.11-7-qcom
cat artifacts/tft50-7.0.11-7-qcom/build.log
```

Скрипт загружает точный исходник Linux, сверяет SHA-256, применяет два
патча и собирает модуль с установленными заголовками. Для сборки без сети
можно передать `--source /path/to/edt-ft5x06-stock.c`; хеш проверяется также.
Каталог результата должен быть новым. Протокол и хеши — в `build.json`.
При проверке использовался GCC 13.3; предупреждение об отличии от GCC 12.2,
которым собрано ядро, не помешало сборке и загрузке модуля.

Сначала вывести проверенный план, затем применить его:

```sh
sudo python3 tools/target/linux/tft50/install.py \
  --build artifacts/tft50-7.0.11-7-qcom --entry "$tft_entry"

sudo python3 tools/target/linux/tft50/install.py \
  --build artifacts/tft50-7.0.11-7-qcom --entry "$tft_entry" --apply
```

Без `--apply` изменяется только временный каталог для проверки DTB.
Установщик проверяет модель, ядро, хеши, `vermagic`, отсутствие другого
модуля-замены и отсутствие `edt-ft5x06` в initramfs. Он проверяет объединение
DTB со всеми выбранными оверлеями через `fdtoverlay`.

При установке:

- В каталог `dtbo` выбранного ядра на EFI добавляются
  `q6a-btt-tft50-display.dtbo` и `q6a-btt-tft50-power.dtbo`.
- Если штатный Raspberry Pi overlay был активен, он заменяется в записи
  и сохраняется с суффиксом `.disabled`. Если он не был активен, новые
  оверлеи добавляются к имеющимся.
- Модуль устанавливается в
  `/lib/modules/7.0.11-7-qcom/updates/q6a-tft50/edt-ft5x06.ko`;
  `depmod` должен выбрать его. Штатный модуль остаётся на месте.
- Исходный DTB, порядок остальных оверлеев и прочие строки EFI-записи
  сохраняются. Для DTB и остальных оверлеев проверяются контрольные суммы.
- В `/var/backups/q6a-tft50-…/` сохраняются исходные и новые байты файлов,
  `transaction.json` и самостоятельная копия скрипта отката. Создаётся
  EFI-запись `Q6A-before-tft50.conf` с прежними параметрами загрузки.

Существующая установка не перезаписывается. Скрипт не меняет загруженный
модуль, не перестраивает initramfs и не перезагружает плату.
Сохраните напечатанный путь отката, затем выполните:

```sh
sudo reboot
```

## Проверка результата

```sh
cat /sys/class/drm/card*-DSI-1/status
cat /sys/class/drm/card*-DSI-1/enabled
cat /sys/class/drm/card*-DSI-1/modes
modinfo -n edt_ft5x06
cat /sys/bus/i2c/devices/13-0038/input/input*/name
cat /sys/bus/i2c/devices/13-0038/input/input*/poll
sudo journalctl -b -k --no-pager | grep -Ei 'edt|ft5|touch|rpi_touchscreen|attiny|dsi'
```

Ожидаются `connected`, `enabled`, `800x480`, путь модуля в `updates/q6a-tft50`,
устройство `generic ft5x06 (00)` и период `17`. Номера `inputN`, `eventN`
и `cardN` могут меняться. В этой проверке I2C13 сохранялся; на другой
конфигурации шину нужно определить заново.

Для проверки событий установите `evtest`, запустите `sudo evtest` и
выберите тачскрин из списка. Проверьте нажатия, отпускания, движение и
попадание в элементы рабочего стола по всей площади. Само наличие
input-устройства ещё не подтверждает работу касаний. В исходной проверке
за 45 секунд получены 467 input events, из них 356 изменений касаний;
точность координат подтвердил владелец.

Если экран полностью тёмный и есть `Failed to read REG_ID reg: -5` у
`13-0045`, проверьте питание LCD и фактически загруженный power overlay.
Если изображение есть, но касаний нет — путь выбранного модуля, отсутствие
IRQ в активном DT, значение `poll` и события evdev. Не опрашивайте
контроллер через `i2cdump`/`i2cget`, пока им управляет драйвер.

## Откат и обновления

Для установки новым инструментом используйте **точный путь**, напечатанный
при `--apply`, например:

```sh
sudo python3 /var/backups/q6a-tft50-REPLACE/install.py \
  --rollback /var/backups/q6a-tft50-REPLACE
sudo reboot
```

`REPLACE` заменяется идентификатором своей резервной копии. Откат возвращает
сохранённые файлы, убирает добавленные и выполняет `depmod`. Если файл
изменён после установки, откат остановится до записи; нужно сначала
сопоставить его с `transaction.json`, чтобы сохранить более поздние правки.
При недоступном DSI используйте SSH, HDMI или прежнюю запись EFI.
Выбор recovery-записи сам по себе не удаляет модуль-замену с диска.

**Для исходной аппаратной установки от 2026-10-15** резервные копии имеют
старый формат: `manifest.json` и `rollback.sh`. Найдите каталог
`/var/backups/q6a-tft50-touch-…/` и выполните его `rollback.sh` **первым**,
затем `rollback.sh` из `/var/backups/q6a-tft50-…/` для питания и перезагрузку.
Эти копии возвращают состояние до соответствующего этапа, когда штатный
Raspberry Pi overlay уже был включён пользователем. Новый `--rollback`
к старому формату неприменим.

При обновлении ядра модуль из каталога предыдущей версии не используется.
Нужны повторная адаптация/сборка и проверка EFI-записи нового ядра.
Не копируйте старый `.ko` в новое ядро. Повторное управление оверлеями через
`rsetup` может восстановить штатный DTB или заново сформировать их список;
проверяйте сохранность TFT50 и собственных камерных настроек после таких операций.
