# BIOS для Linux и Android

**Разработка: команды новых обёрток ещё не проверены на плате.**
Основной маршрут: [прямой Linux](linux-bios.md) и [прямой Android](android-ufs.md).

Здесь зафиксированы **два отдельных профиля SPI**. Один общий BIOS с меню
Linux / Android остаётся отдельной задачей: успешный запуск каждой системы
с собственным образом не доказывает совместимость одного образа с обеими.

| Профиль | Образ в проверенном пакете | Назначение | Известный результат |
| --- | --- | --- | --- |
| Linux | `recovery/spi-after-linux-restore.bin` | UEFI и установленный Linux с NVMe | Ubuntu запускалась с `module_blacklist=i2c_qcom_geni` |
| Android | `images/spi-android-ufs30-power-test.bin` | Android 15 на Toshiba UFS | Программный reset, завершение Android и интерфейс HDMI подтверждены |

Хеши и состояние проверки находятся в
[bios-profiles.json](../manifests/bios-profiles.json). Это полные снимки SPI
конкретной платы, включая сохранённую конфигурацию. Linux образ возвращает
сохранённые настройки UEFI; свои последующие настройки сначала сохраните в бэкапе.

## Почему это разные образы

В имеющемся Linux `flat_build` XBL расположен с LBA 925; SPI также содержит
XBL_CONFIG, AOP, TZ, HYP, ImageFv, PILFv и другие загрузочные компоненты.
В Android пакете SPI содержит GPT и XBL с LBA 6; следующие компоненты находятся
в UFS. Android XBL содержит `DefaultBDSBootApp = "LinuxLoader"`.
Наличие строки NVMe в бинарнике само по себе не подтверждает загрузку Linux.

Radxa отдельно требует BIOS из Android пакета для своего Android 15:
[официальная инструкция](https://docs.radxa.com/en/dragon/q6a/other-system/android).
У обычного BIOS есть Boot Manager и управление UEFI записями:
[описание интерфейса](https://docs.radxa.com/en/dragon/q6a/low-level-dev/bios).
Это описание возможностей меню, а не подтверждение совместимости со штатным
Android загрузчиком. Смешивание файлов и XML двух пакетов не является рабочим рецептом.

## Переключить только BIOS

Сначала подключите [проверенный пакет](artifacts.md). Из корня репозитория:

```powershell
& .\scripts\Switch-Q6A-Bios.ps1 -Profile Linux
& .\scripts\Switch-Q6A-Bios.ps1 -Profile Android
```

Без `-Action` выполняется только проверка файлов, без обращения к USB.
Чтобы записать профиль, переведите плату в EDL и откройте PowerShell от
администратора. Для каждой новой записи задайте **новый RunId**.

Для Linux с уже установленной Ubuntu на NVMe:

```powershell
$run = 'bios-linux-001'
& .\scripts\Switch-Q6A-Bios.ps1 -Profile Linux -Action Flash -RunId $run
```

Для возврата в **уже установленный и исправленный** Android на UFS:

```powershell
$run = 'bios-android-001'
& .\scripts\Switch-Q6A-Bios.ps1 -Profile Android -Action Flash -RunId $run
```

Каждая команда сначала сохраняет 32 МиБ текущего SPI с SHA-256, затем записывает
целевой образ и сравнивает полное обратное чтение. Android профиль дополнительно
читает текущий `xbl_a` на плате: он уже должен содержать проверенный патч.
При исходном или другом XBL запись Android SPI прекращается; сначала нужна
[установка Android с исправлением UFS](android-ufs.md).

Этот маршрут не вызывает `Provision`, `FlashUfs`, `PatchUfs` или `RestoreUfs`.
Android и его пользовательские данные при переключении BIOS не перезаписываются.

После `BIOS FLASH VERIFIED` полностью снимите питание на 10 секунд. Для Linux
подключите NVMe с установленной системой; для изолированной проверки Android
отключите NVMe и SD. Подайте питание без удержания EDL и сохраните UART лог.

Программную перезагрузку можно проверить отдельно, ещё находясь в EDL:

```powershell
# Используйте профиль и RunId только что выполненного Flash.
& .\scripts\Switch-Q6A-Bios.ps1 -Profile Android -Action Boot -RunId $run
```

Для Linux замените профиль на `Linux`. Boot заново читает SPI **с платы** и
сравнивает с выбранным образом перед reset. Старого readback файла недостаточно.

## Нормальная загрузка Linux

Для имеющегося NVMe рабочая система — Ubuntu, ядро `7.0.11-7-qcom`.
Командная строка рабочего пункта должна содержать:

```text
module_blacklist=i2c_qcom_geni
```

В этой установке вариант no camera без blacklist ещё приводил к сбою I2C.
Изменение BIOS не добавляет параметр ядра в GRUB. После загрузки проверьте:

```sh
cat /proc/cmdline
uname -r
findmnt /
sudo journalctl -b -k | tail -n 80
```

Если рабочий параметр был добавлен только однократно, внесите его в
`GRUB_CMDLINE_LINUX_DEFAULT` в `/etc/default/grub`, сохранив другие параметры,
и выполните `sudo update-grub`. При существующем `module_blacklist` добавьте
`i2c_qcom_geni` в его список через запятую. Выберите рабочий Ubuntu пункт по
умолчанию средствами используемого загрузчика. В UEFI также выставьте нужную
запись NVMe первой и сохраните настройки. Так очередной старт не потребует
повторного выбора через F12. Пути EFI и названия пунктов зависят от образа Linux;
не подставляйте случайный номер пункта из другой установки.

В Linux должны завершиться загрузка до входа/рабочего стола и повторный старт
без ручного выбора. Наличие blacklist отключает этот I2C драйвер, что влияет
на устройства, которые через него работают. Проверка только вывода BIOS не
подтверждает исправление Linux. Установка Linux на UFS здесь не проверена.

## Нормальная загрузка Android

После прошивки должны пройти XBL, UEFI и ядро, затем появиться интерфейс.
С подключённым ADB проверьте:

```powershell
adb shell getprop ro.build.version.release
adb shell getprop sys.boot_completed
adb shell getprop init.svc.bootanim
```

Ожидаются `15`, `1`, `stopped`. Повторите обычную перезагрузку и холодный старт.
Холодный старт, длительная стабильность и переключение обоих профилей новым
скриптом ещё не подтверждены на плате. Эти проверки нельзя заменять успешным
SHA-256 обратного чтения.

## Вернуть прежний SPI

При ошибке снова войдите в EDL. Используйте профиль **попытки записи** и её RunId:

```powershell
& .\scripts\Switch-Q6A-Bios.ps1 -Profile Android -Action Restore -RunId 'bios-android-001'
```

Restore записывает SPI из бэкапа перед этой попыткой и проверяет readback.
Это может вернуть Linux BIOS, если перед попыткой стоял Linux. Сохранённая
пометка профиля не означает, что бэкап содержит тот же профиль. UFS не меняется.
