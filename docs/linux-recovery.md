# Возврат SPI и загрузка Linux с NVMe

**Разработка: команды новых обёрток ещё не проверены на плате.**
Основной маршрут: [прямой Linux](linux-bios.md) и [прямой Android](android-ufs.md).

В готовом пакете сохранён рабочий Linux SPI образ. Он использовался для
загрузки Q6A с имеющегося NVMe, Ubuntu и ядра `7.0.11-7-qcom`.
Это восстановление BIOS, а не установка Linux на UFS.

Для обычного переключения Linux / Android используйте
[профили BIOS](bios-profiles.md): этот маршрут автоматически сохраняет текущий
SPI перед записью, не переустанавливая систему на UFS.

## Вернуть состояние SPI до новой установки

После ручного входа в EDL, из корня репозитория:

```powershell
$run = 'reinstall-001'
& .\scripts\Install-Q6A-Android.ps1 -Stage RestoreSpi -RunId $run
```

Используйте RunId той установки, для которой выполнен BackupSpi.
Скрипт проверит SHA-256 бэкапа, запишет его и сравнит полное обратное чтение.
RestoreSpi возвращает только SPI. Данные Android и конфигурация LUN не восстанавливаются.

RestoreUfs возвращает оригинальный Android `xbl_a`, сохранённый **после FlashUfs,
перед PatchUfs**. Это не прежний Android и не весь UFS. На этом Toshiba исходный
XBL возвращает прежнее зависание, поэтому RestoreUfs нужен для возврата исходного
образа, а не как способ запустить Android.

## Использовать сохранённый Linux BIOS

```powershell
$run = 'bios-linux-recovery-001'
& .\scripts\Install-Q6A-Android.ps1 -Stage BackupSpi -RunId $run
& .\scripts\Install-Q6A-Android.ps1 -Stage RecoveryLinux -RunId $run
```

При самостоятельном возврате Linux BIOS используйте новый RunId для BackupSpi.
Внутри незавершённой установки Android используйте её RunId и существующий бэкап.

После `VERIFIED` выключите питание, подключите NVMe и включите без EDL.
На сохранённом NVMe используйте подготовленный пункт Ubuntu **с отключённым I2C**:

```text
module_blacklist=i2c_qcom_geni
```

Пункт no camera в этом Linux всё ещё приводил к ошибке I2C. Выбор названия
overlay сам по себе не подтверждает, что нужный параметр ядра применён.
Рабочий возврат SPI не создаёт GRUB пункт и не восстанавливает содержимое NVMe.

## UFS в Linux

Модуль определялся как Toshiba и читался из Linux. Для короткой диагностики
применялись отключение runtime suspend (`power/control=on`) и auto hibern8.
Успешное чтение 256 МиБ и отсутствие новых ошибок после него — ограниченный
функциональный результат. Установка Linux на этот UFS и долговременная проверка
в этом репозитории не заявлены.
