# Radxa Dragon Q6A

Репозиторий посвящён одноплатному компьютеру **Radxa Dragon Q6A**:
аппаратной документации, подготовке ОС, настройке периферии, диагностике
и восстановлению. Здесь собраны оригиналы документов производителя,
справочные заметки и планы экспериментов с конкретной платой.

## Получение репозитория

```sh
git clone git@github.com:pOmelchenko/radxa_dragon_q6a.git
cd radxa_dragon_q6a
```

## Имеющийся экземпляр платы

Сведения об ОС и накопителях обновлены **10 октября 2026 года**.
Камерные планы сохранены по сведениям от 23 сентября 2026 года:

| Компонент или направление | Зафиксированное состояние |
| --- | --- |
| Плата и память | Radxa Dragon Q6A, **12 ГБ ОЗУ**. Ревизия PCB и вариант CS/ES не указаны. |
| Linux на NVMe | **NVMe SSD 256 ГБ**, Ubuntu, ядро `7.0.11-7-qcom`. Загрузка прошла с `module_blacklist=i2c_qcom_geni`; версия дистрибутива и источник образа не зафиксированы. |
| План по ОС | Переход на **Armbian Minimal/CLI без графического рабочего стола**. |
| Камера | Для проверки совместимости с Q6A заказана цветная **AR0234 / DECXIN-3478V1 с объективом 200°**. Получение модуля и успешный захват изображения не зафиксированы; см. [план проверки](camera-research.md#эксперимент-с-ar0234). |
| Android на UFS | **TOSHIBA THGJFCT2T84BAKCB rev 0100, UFS 3.0, 512 ГБ**. Android 15 загрузился после программного reset с исправленным XBL в UFS и SPI. |

Запись Linux BIOS и запуск Android подтверждены результатами аппаратного
сеанса; инструкции приведены ниже. Захват изображения и синхронизация камер
пока не подтверждены.

## Прошивка: проверенные прямые команды

Основной маршрут использует **исправленный edl-ng v2**. В выполненных попытках
Qualcomm GUI возвращал ошибки; успешные операции зафиксированы отдельно.

| Задача | Инструкция | Результат |
| --- | --- | --- |
| Подготовить файлы, EDL и бэкап SPI | [Подготовка](docs/direct-edl.md) | Точный EXE, программаторы и контрольные суммы |
| Прошить BIOS для Linux с NVMe | [Linux BIOS](docs/linux-bios.md) | Rawprogram выполнен; 18 payload совпали с readback; Ubuntu запускалась с I2C blacklist |
| Развернуть Android 15 на Toshiba UFS | [Android UFS](docs/android-ufs.md) | UFS XBL и SPI сверены; Android завершил загрузку и вывел интерфейс HDMI |
| Проверить файлы и происхождение исправлений | [Файлы](docs/artifacts.md), [патчи](docs/xbl-workaround.md) | SHA-256, описание XBL и полный патч edl-ng |
| Разобрать NAK, тайм-аут или пустой экран | [Диагностика](docs/troubleshooting.md) | Наблюдавшиеся ошибки и точки остановки |

Подробности комплекта и состояние проверок: [маршрут прошивки](docs/flashing.md).
Это результат одного Q6A с 12 ГБ ОЗУ и указанным UFS. Android подтверждён
после reset; холодный старт, длительная стабильность и новый полный прогон
с пустого модуля пока не подтверждены. `/data` осталось 45 ГиБ в разделе
около 444,36 ГиБ; расширение ещё не выполнено. Полная прошивка и личные
логи хранятся отдельно и сейчас не опубликованы в GitHub Release.

Новые скрипты установки и переключения BIOS сохранены как разработка:
проверки без платы не считаются аппаратной проверкой. Основные инструкции
дают команды напрямую и отмечают фактически полученный результат.

## Что фиксировать в экспериментах

- Ревизию PCB, вариант микросхемы, модель SSD, образ ОС, загрузочную прошивку
  и ядро. Перед заменой ОС сохранить сведения о текущей установке Ubuntu.
- Результаты холодного запуска без монитора, восстановления SSH и сети,
  а также работы NVMe на выбранном образе Armbian.
- Распиновку AR0234, проверенную схему переходника и программную настройку.
  Сначала проверить один поток, затем внешний запуск и несколько камер.
- Результаты проверок Ethernet, Wi-Fi, накопителей, GPIO, дисплея
  и другой периферии.
- Скрипты и патчи вместе с инструкциями, наблюдаемыми результатами,
  ограничениями и способом восстановления.

Подготовленный план, успешная сборка и проверка на физической плате
должны быть отмечены отдельно. Образы ОС, сборочные каталоги и временные
результаты экспериментов не добавляются в Git.
